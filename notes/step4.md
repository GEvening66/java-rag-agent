# 第 4 课笔记：v1 agent 化 —— 引用溯源校验（4a）

## 核心概念：接地率（grounding）
- **定义**：回答里的字符，有多大比例能在"被引用的资料块"里找到（0~1）
- **为什么需要**：模型说"根据资料[1]"**不代表真的在[1]里**——它可能编造。
  用程序校验，不靠模型自觉，这是防幻觉的硬防线
- **局限（要主动说）**：字符级接地是**基线方案**，对"换说法"的忠实回答会误判；
  第 5 课升级为语义级（LLM-as-judge）

## 4a 流程（这就是 agent 的最小闭环）
```
检索 top-3 → 模型输出 JSON{answer, citations}（结构化输出）
    → 程序校验：引用编号合法性 + 每个引用的接地率（举证）
    → 接地率 < 0.5 → 可疑 → 让模型重答一次（反思重试，range(2) 防死循环）
    → 输出最终回答 + 每个引用的 ✅/⚠️
```

## 预期输出长什么样

```

```
（k 还是 3，所以这个 demo 会**故意暴露**模型编引用——这是本课最精彩的一课）

## 面试口径（4a 做完要能答）
1. "你的系统怎么防模型编引用？" → 程序级接地率校验 + 校验不过重答，不靠提示词自觉
2. "字符级接地率太弱了怎么办？" → 它是基线；升级方向是语义级校验（LLM-as-judge）
   ——主动暴露局限并给改进路径，是加分回答
3. "重答会死循环吗？" → 不会，最多重试 1 次（range(2)），有硬上限
4. "模型不输出 JSON 怎么办？" → 正则兜底提取 + 解析失败降级提示

## 实测记录（2025，k=3）
**问题 1「HashMap 的负载因子是多少？」**
- 回答正确 + 引用 [1]，接地率 93% ✅ 通过 —— 引用校验闭环工作正常

**问题 2「volatile 能保证原子性吗？」（高光时刻）**
- 模型回答内容正确，但**没有给引用**，并诚实声明：
  "您提供的资料中没有直接提到 volatile 的原子性，因此回答基于 Java 基础知识"
- 校验器：空引用 → ⚠️ 可疑 → 触发反思重答 → 第二次仍无引用 → "重试后仍未通过"
- **三层解读**：
  1. 模型表现好：没编引用（防幻觉系统起作用了——模型被迫诚实）
  2. 校验器工作正常：空引用被拦截、重答、如实报告
  3. 根因在**检索**：k=3 时答案块排第 4（第 3 课已定位！）→ 资料里没答案
     → 模型无从引用 → 全链路"诚实失败"
- **设计取舍（面试深水区）**：严格引用校验会拒绝"答对但没依据"的回答。
  正确性 ≠ 可引用性。生产里要权衡：拒答（安全） vs 可用性（体验）
- **待验证修复**：K=3 → K=5，重跑 volatile，答案块进 top-5 后应该 ✅ 通过

## 4b：多轮澄清追问（agent 的"规划"要素）

### 为什么需要澄清
用户问得模糊（"讲讲 HashMap"），检索质量会崩——"讲讲 HashMap"向量化后
找不到具体靶子。先追问澄清，把模糊意图变成明确意图，检索才有意义。
**这是 agent 的"规划"要素**：决定"我现在缺什么信息"。

### 怎么判断宽泛（needs_clarification）
规则（满足任一即追问）：
1. 含宽泛动词：讲讲/介绍/说一下/概述/说说/谈谈
2. 去空白后长度 < 8 字符（"HashMap"、"反射"这种意图不明）
3. 其余直接回答

### 追问流程（05_clarify.py）
```
用户提问 → 宽泛？ → 是：追问 1 次（模板化提问）→ 用户补充
        → 否：直接检索回答
把澄清内容拼进问题（记忆）→ 检索 top-5 → JSON → 引用校验 → 回答
MAX_TURNS=3 防死循环
```

### 面试口径（4b）
1. "为什么需要澄清？" → 模糊问题毁检索，先问清楚是 agent 的规划要素
2. "怎么判断模糊？" → 启发式规则（宽泛词/过短）；升级路径：用 LLM 判断
3. "追问会不会烦用户？" → 最多 1 次 + 模板化提问，体验优先
4. "追问会死循环吗？" → 不会，MAX_TURNS 硬上限

- 交互实测通过："讲讲 HashMap"触发追问 → 补"线程安全" → 带引用回答
- 讲解验收：流程表述正确（判断宽泛→反问→澄清内容拼进问题→检索回答）
