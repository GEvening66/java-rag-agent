# 第 2 课笔记：embedding → 检索 → 生成（第一次跑通完整 RAG 链路）

## 三个核心概念

### 1. Embedding（向量化）
把一段文字变成一串数字（向量）。**语义相近的句子，向量在空间里也接近**：
"HashMap 的负载因子是多少" 和 "HashMap 默认加载因子是 0.75" 意思接近 → 向量距离近。
这就是检索能"找到相关内容"的根本原因：不是匹配关键词，而是匹配**意思**。
（BGE-M3 是中文效果好的开源 embedding 模型，硅基流动提供免费接口）

### 2. 余弦相似度
衡量两个向量"方向是否一致"：cos = (a·b) / (|a|·|b|)，取值 [-1, 1]，越接近 1 越相似。
为什么不用欧氏距离？向量的长度受文本长短影响，余弦只看方向不看长度，更适合文本。

### 3. top-k 检索
不取最相似的那 1 块，而是取前 k 块（这里 k=3）：
- 单个块信息可能不完整，多块互补
- 模型一次能读多块，综合回答
代价：k 太大 → 塞入无关内容 → 回答变差、成本变高。
**k 是你要调的第一个参数**（第 5 课会做实验对比）。

## 完整链路（第 2 课跑通）
```
文档 → 切分(chunk，第 1 课) → 向量化(embedding) → 存向量
问题 → 向量化 → 余弦相似度检索 top-k → 拼 prompt → DeepSeek 回答
```

## 理解题
1. 为什么检索用"余弦相似度"而不是"字符串包含"？
2. 为什么取 top-3 而不是 top-1？
3. 如果检索到的 3 块资料都和问题无关，模型会怎么回答？（提示：看 prompt 里的那句话）

## 理解题答案（已验收 2025）
1. 字符串包含只能做字面匹配，处理不了"意思相同、说法不同"（同义词/改写）；余弦相似度把文本映射到向量空间，语义相近的文本向量距离近，实现语义检索。
2. top-1 单块信息可能不全，多块互补更稳；但 k 太大会塞入噪声块（实测 top-3 混进了 Integer 缓存），k 是第 5 课要实验调优的参数。
3. prompt 里明确要求：资料里没有相关内容时直接回答"资料中没有相关信息"，不编造（拒答 = 防幻觉第一道防线）。

## 02_rag.py 导读（动手前先读一遍，从上往下 5 段）

1. **导入 + 加载**：用 importlib 加载你写的 `01_chunk.py`（文件名以数字开头，普通 import 用不了）；加载 `config.py` 拿你的 Key
2. **两个客户端**：`chat_client`（DeepSeek 问答）、`embed_client`（硅基流动向量化）——两者都是 OpenAI 兼容协议，代码一模一样，只换了 base_url 和 key
3. **`build_index()`**：读 `data/` 文档 → 用你的 `chunk_text` 切块 → `embed_texts` 批量向量化 → 存 `cache/`（chunks.json + chunks_vecs.npy）。改了文档想重建就删 `cache/` 目录
4. **你的作业 `search_top_k()`**：余弦相似度 + 取前 k 个下标（就是 TODO 那 2~4 行）
5. **`main()`**：问题向量化 → 检索 top-3 → 拼 prompt（带 [1][2][3] 引用编号）→ DeepSeek 回答

## 常见报错排查（第 2 课）
| 报错 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'openai'/'numpy'` | 依赖没装 | `pip install openai numpy` |
| `AuthenticationError` / `401` / `Invalid API key` | Key 不对或没填 | 检查 `config.py` 两个 Key 有没有复制全（sk- 开头） |
| `ConnectionError` / 超时 | 网络问题 | 换个网络/重试；确认能打开 platform.deepseek.com |
| `Invalid URL` / `404` | base_url 拼错 | 检查 `config.py` 两个 BASE_URL 是否原样 |
| 出现 `cache/` 目录但检索为空 | `search_top_k` 没实现 | 检查 TODO 处是否写了代码（先别管效果，先能返回 3 个下标） |
| 中文输出乱码 | 控制台编码问题 | 在命令前加 `$env:PYTHONIOENCODING="utf-8"`（PowerShell）或 `set PYTHONIOENCODING=utf-8`（cmd） |

**一个判断技巧**：报错信息最下面一行的 `Error: ...` 才是真正原因，往上翻的堆栈可以先忽略。
