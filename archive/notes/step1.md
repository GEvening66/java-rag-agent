# 第 1 课笔记：为什么 RAG 要先"切分"？

## 核心问题：模型不知道你的私有文档
大模型（比如 DeepSeek）训练时没见过你手里的 Java 教程文档。
你直接问它，它只能凭"记忆"回答，可能过时、可能编造。
**RAG 的思路**：把文档先存起来，回答问题时先把相关的部分"找出来"，
再让模型**只基于找到的内容**回答。这样答案有依据、有出处。

## 为什么必须"切分"（chunking）？
- 模型每次能处理的文本有限（上下文窗口），整本书塞不进去
- 检索需要"精准定位"：问题可能只和文档里某一小段相关
- 所以要把长文档切成**小块**，检索时按块找，找到哪块就把哪块喂给模型

## 两个关键参数
| 参数 | 含义 | 直觉 |
|---|---|---|
| `chunk_size` | 每块多长（字符数） | 太短没上下文，太长检索不精准 |
| `overlap` | 相邻两块重叠多少 | 防止关键句恰好被"一刀切开"，在相邻块里都能完整出现 |
