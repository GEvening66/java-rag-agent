# Java 多线程基础（示例文档，可替换成你自己的资料）

## 创建线程的两种方式
方式一：继承 Thread 类，重写 run 方法。
方式二：实现 Runnable 接口，把实例传给 Thread 构造器。
实现 Runnable 更推荐，因为 Java 是单继承，实现接口不占用继承位，也便于共享任务逻辑。
JDK 8 之后还可以用 lambda 表达式直接写 Runnable。

## synchronized 关键字
synchronized 是内置锁（监视器锁），可以修饰方法或代码块。
它保证同一时刻只有一个线程能进入临界区，并且保证可见性（释放锁时把修改刷新到主内存）。
锁是可重入的：同一个线程可以多次获取同一把锁，不会把自己锁死。

## volatile 关键字
volatile 保证可见性但不保证原子性：被修饰的变量，每次读取都从主内存拿最新值，
写入后立刻对其他线程可见。它适合"一个线程写、多个线程读"的开关标志场景，
但不适合 i++ 这类读改写操作（需要原子性，应该用 AtomicInteger 或锁）。

## wait / notify 与等待通知机制
wait 让当前线程释放锁并进入等待状态，notify 随机唤醒一个等待线程，notifyAll 唤醒全部。
wait 和 notify 必须在 synchronized 块内使用，否则抛 IllegalMonitorStateException。
经典的"生产者-消费者"模型就是基于等待通知机制实现的。

## 线程池 ThreadPoolExecutor
核心参数：核心线程数 corePoolSize、最大线程数 maximumPoolSize、
空闲存活时间 keepAliveTime、任务队列 workQueue、拒绝策略 handler。
任务提交时：先让核心线程处理；核心线程满则进队列；队列满则开新线程到最大；
线程数到最大且队列满则执行拒绝策略（如 AbortPolicy 抛异常）。
用线程池可以避免频繁创建销毁线程的开销，也便于控制并发度。

## 死锁的四个必要条件
互斥、占有且等待、不可剥夺、循环等待。打破任意一个就能避免死锁，
工程上常用"统一加锁顺序"来打破循环等待。
