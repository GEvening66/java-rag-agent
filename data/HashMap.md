# HashMap 原理（示例文档，可替换成你自己的资料）

HashMap 是 Java 中最常用的集合之一，底层是一个"数组 + 链表 + 红黑树"的结构。

## 存储结构
HashMap 内部维护一个 Node 数组（table），每个数组位置叫一个桶（bucket）。
存入键值对时，先对 key 计算 hash 值，再用 hash 对数组长度取模，决定放在哪个桶。
如果多个 key 落进同一个桶，就用链表把冲突的节点串起来（拉链法）。
JDK 8 开始，当链表长度超过阈值（默认 8）且数组长度达到 64 时，链表会转成红黑树，
把最坏情况下的查找时间从 O(n) 降到 O(log n)。

## hash 与扰动函数
JDK 8 的 hash 计算是：hash = (h = key.hashCode()) ^ (h >>> 16)，把高 16 位也参与运算，
减少哈希碰撞。取模用的是 (n - 1) & hash，因为数组长度是 2 的幂时，位运算等价于取模且更快。

## equals 与 hashCode 的约定
如果两个对象 equals 相等，它们的 hashCode 必须相等；反过来不要求。
重写 equals 时通常必须重写 hashCode，否则 HashMap 可能找不到已经放入的 key。

## 负载因子与扩容
默认负载因子是 0.75，意思是当元素个数超过 容量 × 0.75 时触发扩容。
扩容时容量翻倍（变成原来的 2 倍），所有元素要重新计算桶位置（rehash）。
扩容是代价较高的操作，所以预估元素数量时，最好在构造时指定合适的初始容量。

## 线程安全
HashMap 不是线程安全的。多线程环境下并发 put 可能导致数据错乱甚至死循环（旧版本）。
需要线程安全时，用 ConcurrentHashMap 或 Collections.synchronizedMap。
